# MS-4 evidence — safe message experience

Recorded on 2026-08-14 on the local macOS arm64 development host.

## Delivered

- Terminal control and bidi-override removal for message metadata and bodies.
- Plain-text-first rendering with an in-process HTML-to-text fallback.
- Explicit `--html --open` flow that writes escaped, inert cached HTML.
- Streamed attachment download with a 25 MiB default limit, advertised-size
  verification, incomplete-file cleanup, exclusive creation, traversal and
  reserved-name rejection, symlink protection, and explicit overwrite.
- Shell-free clipboard and browser command construction.
- Interactive new-message review with read, acknowledge, skip, and quit actions.
- Implemented non-secret configuration get/set/unset operations.
- Replaced the historical README and man page with v2 behavior and safety
  guidance.

## Performance

The optimized binary is 2,054,016 bytes. A direct-exec Hyperfine run used 30
warmups and 100 measured runs:

| Command | p95 | p99 |
| --- | ---: | ---: |
| `tmpmail --help` | 4.72 ms | 5.02 ms |
| `tmpmail --version` | 7.42 ms | 7.81 ms |

`/usr/bin/time -l tmpmail --help` reported maximum RSS of 2,097,152 bytes. The
offline startup and RSS budgets pass on this host. The static top-level help
fast path was introduced after profiling showed Clap construction dominated the
short command; nested help remains generated by Clap.

## Remaining boundaries

- Native Linux smoke validation remains a later cross-platform gate.
- Browser and clipboard availability depends on platform commands documented in
  the README; construction is tested without launching user applications.
- Live attachment delivery/download remains gated on separately authorized
  provider canaries.
